## 2. 구현된 게임 루프

```
[가게 화면 - 영업 전]
	│
	│ 영업 개시 클릭
	▼
[BusinessDay.start_day()]
  · 오늘의 손님 목록(8~12명) 생성
  · 시간대별 손님 수 + 미니게임 비율 결정
  · 각 손님의 등급(★1~★4) 무작위 결정 (진행도 분포 기반)
  · 각 손님의 레시피 미리 생성
  · 각 손님의 보상 미리 계산
	│
	▼
[손님 순차 처리]
	│
	├─ 아침 (2명, 기억력 70% / 스피드 30%)
	├─ 점심 (4~6명, 기억력 30% / 스피드 70%)
	└─ 저녁 (2명, 50/50)
	│
	├─ 각 손님마다:
	│   │
	│   ▼
	│   [OrderPanel - 주문 수락/거절]
	│     · 종이쪽지가 테이블 아래에서 슬라이드 인
	│     · 표시 정보: 게임 종류 / 별점 / 햄버거 실루엣 / 보상
	│     · 레시피는 노출되지 않음 (메모리 게임 답안 보호)
	│     · [거절] [수락] 버튼
	│     │
	│     ├─ 거절 → 종이쪽지 슬라이드 아웃
	│     │         declined 카운트 +1
	│     │         가게 화면 1초 → 다음 손님
	│     │
	│     └─ 수락 → 종이쪽지 슬라이드 아웃
	│              │
	│              ▼
	│           [미니게임 시작]
	│             · 메모리: 종이쪽지 재등장(재료 표시) → n초 후 가림 → 입력
	│             · 스피드: 카운트다운 → 종이쪽지 재등장(재료 표시) → 입력
	│             · 햄버거 1개 완성마다 보너스 시간 (+5초)
	│             · 성공 → 정상 보상 / 실패 → 최소 보상
	│             · GameState에 돈 누적
	│             · BusinessDay에 시간대별 매출 기록
	│             · 가게 화면 1초 → 다음 손님
	│
	▼
[영업 마감]
	│
	▼
[DailyReportPanel]
  · 처리한 손님 / 놓친 손님 / 거절한 손님
  · 시간대별 매출
  · 총 매출
	│
	│ 확인 클릭 → SaveSystem.save_game()
	▼
[가게 화면 복귀]
```

## 4. 새 데이터 모델 상세

### 4.1 OrderTier (주문 등급)

각 주문 한 건의 "복잡도와 보상"을 담는 Resource.

```gdscript
@export var tier_id: String          # "tier_1" ~ "tier_4"
@export var star_count: int           # 1 ~ 4
@export var base_reward: float        # 1.0 / 2.0 / 4.0 / 7.0
@export var min_recipe_length: int    # 빵 사이 재료 수 최소
@export var max_recipe_length: int    # 빵 사이 재료 수 최대
@export var speed_burger_count_min: int  # 스피드 게임 햄버거 개수 최소
@export var speed_burger_count_max: int  # 스피드 게임 햄버거 개수 최대
```

### 4.2 GameState 진행도 함수

레벨에 따라 자동 결정되는 값들:

| 함수 | 역할 |
|---|---|
| `get_active_ingredient_count()` | 현재 사용 가능한 재료 수 (4/6/7/8) |
| `get_active_ingredients()` | 현재 활성 재료 Resource 배열 |
| `get_slot_ingredients()` | 슬롯에 표시할 재료 (함정 포함 예정) |
| `get_slot_traps_enabled()` | 함정 슬롯 활성화 여부 (레벨 5+) |
| `get_tier_distribution()` | 현재 레벨에서 각 등급이 나올 확률 |

### 4.3 등급 분포

레벨에 따른 등급 출현 비율:

| 레벨 | ★1 | ★2 | ★3 | ★4 |
|---|---|---|---|---|
| 1~4 | 80% | 20% | 0% | 0% |
| 5~9 | 50% | 35% | 15% | 0% |
| 10~14 | 30% | 35% | 25% | 10% |
| 15+ | 15% | 30% | 35% | 20% |

> 초기안. 플레이테스트로 정밀 조정 필요.

### 4.4 보상 계산

- 메모리 게임 성공: `base_reward`
- 스피드 게임 성공: `base_reward × 햄버거 개수`
- 실패 시: 정상 보상 × `failure_reward_ratio` (0.1)
- 거절 시: 보상 없음

## 5. RecipeNote 컴포넌트 상세

종이쪽지 컴포넌트가 두 가지 모드를 가짐. 정보 노출 통제가 핵심.

### 5.1 INFO_ONLY 모드 (OrderPanel용)

- 헤더: 게임 종류 ("커스텀 주문" / "단체 주문") + 별점
- 본문: 햄버거 실루엣 (재료 종류 노출 없음)
- 풋터: 보상 금액 (스피드는 "$X (Y개)")

> **레시피 유출 방지**: 메모리 게임 답안이 OrderPanel에서 노출되지 않도록 INFO_ONLY 모드로 구성.

### 5.2 RECIPE 모드 (MemoryGame, SpeedGame용)

- 헤더: 게임 종류 + 별점
- 본문: 실제 재료 아이콘들 (역순으로 햄버거 모양 표시)
- 풋터: 보상 금액

### 5.3 애니메이션

- `play_slide_in()`: 테이블 아래에서 위로 슬라이드 + 살짝 회전 (-8°~+8°)
- `play_slide_out()`: 아래로 슬라이드 + 회전 0으로 복귀
- `hide_recipe_content()`: CoverOverlay로 본문 가림 (메모리 게임용)

## 6. 데이터 흐름 (시그널 연결)

```
ShopPanel.open_shop_requested
	→ Main._on_open_shop_requested
		→ BusinessDay.start_day()
		→ Main._process_next_customer()
			→ PanelManager.show_panel(ORDER, {customer})

OrderPanel.order_accepted
	→ Main._on_order_accepted()
		→ PanelManager.show_panel(MEMORY_GAME or SPEED_GAME, {recipes, tier})

OrderPanel.order_declined
	→ Main._on_order_declined()
		→ GameState.todays_customers_declined += 1
		→ PanelManager.show_panel(SHOP) [1초]
		→ Main._process_next_customer()

MemoryGamePanel.minigame_finished / SpeedGamePanel.minigame_finished
	→ Main._on_minigame_finished
		→ GameState.add_money()
		→ BusinessDay.record_revenue()
		→ PanelManager.show_panel(SHOP) [1초]
		→ Main._process_next_customer() 또는 _end_business_day()

DailyReportPanel.report_confirmed
	→ Main._on_report_confirmed
		→ SaveSystem.save_game()
		→ PanelManager.show_panel(SHOP)
```

## 7. 저장 시스템

### 7.1 저장 시점

- 영업일 마감 시 (DailyReport 확인)
- 창 닫기 시 (`NOTIFICATION_WM_CLOSE_REQUEST`)
- 백그라운드 진입 시 (`NOTIFICATION_APPLICATION_PAUSED`)

### 7.2 저장 위치

`user://savegame.dat` (OS별 자동 위치)

- Windows: `%APPDATA%/Godot/app_userdata/burger_shop/`
- macOS: `~/Library/Application Support/Godot/app_userdata/burger_shop/`
- Linux: `~/.local/share/godot/app_userdata/burger_shop/`

### 7.3 저장 대상

- money, level
- unlocked_difficulties, unlocked_ingredients
- (placed_decorations 등은 Phase 3에서 추가)
- version (1)

### 7.4 웹 빌드 미적용 사항

- IndexedDB 동기화 (FS.syncfs)
- 포커스 잃음 시 저장
- beforeunload 이벤트 처리

> 데스크탑 환경에서는 정상 작동. 웹 배포 시 backlog 4.7 항목 적용 필요.
