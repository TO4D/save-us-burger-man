# 옵시디언 작업일지 작성 가이드

이 문서는 옵시디언 경로 `C:\Users\tjdgn\Documents\BurgerWhat\작업일지`에 오늘의 작업 내역을 정리할 때 사용할 기준과 템플릿을 정의합니다.

## 1. 목적

- 하루 동안 진행한 작업을 빠르게 회고할 수 있어야 합니다.
- 다음 작업자가 현재 상태를 바로 이해할 수 있어야 합니다.
- 구현 내용, 판단 근거, 남은 이슈가 함께 남아야 합니다.

## 2. 작성 원칙

- 제목은 날짜 기준으로 작성합니다.
  - 예시: `2026-05-19 작업일지`
- 요약은 먼저 쓰고, 세부 내역은 뒤에 정리합니다.
- "무엇을 했다"보다 "무엇이 바뀌었고 왜 바뀌었는지"를 우선 기록합니다.
- 코드 수정이 있었다면 파일명 또는 시스템 단위를 함께 남깁니다.
- 미완료 작업은 반드시 다음 액션이 보이도록 적습니다.

## 3. 권장 구성

하루 작업일지는 아래 순서를 권장합니다.

1. 한 줄 요약
2. 오늘 완료한 작업
3. 주요 변경 사항
4. 이슈 및 판단 사항
5. 남은 작업
6. 다음 작업 우선순위

## 4. 템플릿

아래 템플릿을 복사해서 사용합니다.

```md
# 2026-05-19 작업일지

## 한 줄 요약
- 오늘 작업을 한 문장으로 요약

## 오늘 완료한 작업
- 작업 1
- 작업 2
- 작업 3

## 주요 변경 사항
- 변경 내용
  - 수정한 시스템/기능:
  - 관련 파일/씬/리소스:
  - 변경 이유:

## 이슈 및 판단 사항
- 문제 상황:
- 원인 또는 추정 원인:
- 대응 내용:
- 남은 리스크:

## 남은 작업
- 아직 끝나지 않은 작업
- 확인이 더 필요한 항목

## 다음 작업 우선순위
1. 가장 먼저 할 일
2. 그다음 할 일
3. 여유가 있으면 할 일
```

## 5. 좋은 요약 기준

좋은 요약은 아래 기준을 만족해야 합니다.

- 결과 중심으로 작성되어 있습니다.
- 읽는 사람이 내일 바로 이어서 작업할 수 있습니다.
- 완료/진행 중/보류 상태가 구분됩니다.
- "버튼 수정", "버그 확인" 같은 모호한 표현보다 구체적인 표현을 사용합니다.

예시:

- `주문 패널에서 수락/거절 흐름을 분리하고 상태 전이를 정리했다.`
- `저장 후 다음 영업일 진입 시 초기화 누락 문제를 수정했다.`
- `튜토리얼 문구는 정리했지만 입력 타이밍 이슈는 아직 남아 있다.`

## 6. 권장 작성 예시

```md
# 2026-05-19 작업일지

## 한 줄 요약
- 주문 처리 흐름과 저장 연동 상태를 정리하고, 다음 구현 범위를 다시 좁혔다.

## 오늘 완료한 작업
- 주문 패널의 수락/거절 흐름 점검
- 저장 데이터 복구 시점 확인
- 문서 기준으로 남은 작업 우선순위 재정리

## 주요 변경 사항
- 주문 처리 흐름 정리
  - 수정한 시스템/기능: 주문 패널, 주문 상태 전이
  - 관련 파일/씬/리소스: 관련 스크립트 및 UI 씬
  - 변경 이유: 플레이어 입력 이후 상태 흐름이 한눈에 보이도록 정리하기 위해

- 저장 연동 확인
  - 수정한 시스템/기능: 저장/불러오기 흐름
  - 관련 파일/씬/리소스: 저장 시스템 관련 스크립트
  - 변경 이유: 영업일 재진입 시 데이터 복구 누락 여부를 확인하기 위해

## 이슈 및 판단 사항
- 문제 상황: 일부 흐름은 문서와 실제 구현 상태가 완전히 일치하지 않았다.
- 원인 또는 추정 원인: 기능 추가 후 문서 갱신이 뒤따르지 못했다.
- 대응 내용: 현재 구현 기준으로 상태를 다시 정리했다.
- 남은 리스크: 예외 케이스 테스트가 충분하지 않다.

## 남은 작업
- 거절 이후 후속 피드백 연출 보강
- 저장/로드 경계 조건 테스트
- 작업 현황 문서와 실제 구현 차이 추가 점검

## 다음 작업 우선순위
1. 주문 흐름 예외 케이스 테스트
2. 저장/로드 관련 경계 조건 정리
3. 남은 작업 문서 최신화
```

## 7. 파일명 규칙

- 기본 형식: `YYYY-MM-DD 작업일지.md`
- 같은 날 여러 번 보완하면 하나의 문서를 계속 갱신합니다.
- 필요하면 제목 아래에 마지막 수정 시간을 추가합니다.
  - 예시: `마지막 수정: 2026-05-19 22:40`

## 8. 체크리스트

작성 전 또는 작성 후 아래 항목을 확인합니다.

- 오늘 실제로 바뀐 내용이 드러나는가
- 수정 이유가 적혀 있는가
- 남은 작업이 다음 행동으로 이어지는가
- 내일 봐도 바로 이해 가능한가
- 너무 장황하지 않고 핵심이 먼저 보이는가

## 9. 권장 운영 방식

- 작업 종료 직전 5분 안에 작성합니다.
- 커밋 메시지, 변경 파일, 테스트 결과를 기준으로 요약합니다.
- 문서 내용과 실제 구현 상태가 다르면 구현 상태를 기준으로 적습니다.
- 다음 날 시작 전에 전날 작업일지의 `남은 작업`과 `다음 작업 우선순위`를 먼저 확인합니다.
